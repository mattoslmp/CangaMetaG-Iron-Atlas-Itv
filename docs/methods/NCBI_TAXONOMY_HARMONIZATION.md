# Reproducible NCBI taxonomy harmonisation

## Scope

Taxonomic labels at **Phylum, Order, Family and Genus** are harmonised against the current NCBI taxonomy dump. The procedure changes taxonomic names only. It does not alter the CDS OTU matrix, sample identifiers, taxon-feature identifiers, counts, relative-abundance calculations, statistical inputs or ordination values.

## Source files

- `data/resultado.cds.otu.tab`: immutable CDS count matrix.
- `data/resultado.cds.tax.tab`: original packaged taxonomic classification.
- NCBI taxonomy dump: `https://ftp.ncbi.nlm.nih.gov/pub/taxonomy/taxdump.tar.gz`.
- `data/taxonomy_palette.json`: canonical colours used by the article and app.

## Reproducible command

```bash
python scripts/taxonomy/harmonize_ncbi_taxonomy_and_regenerate.py \
  --download-taxdump
```

For an already downloaded dump:

```bash
python scripts/taxonomy/harmonize_ncbi_taxonomy_and_regenerate.py \
  --taxdump /path/to/taxdump.tar.gz
```

## Name-resolution rule

For every distinct label in Phylum, Order, Family and Genus, the script searches `names.dmp`, checks the candidate node rank in `nodes.dmp`, and retrieves the current NCBI scientific name. A replacement is accepted only when the matched NCBI node has the same rank as the source column. Ambiguous or unmatched labels are preserved unchanged and recorded in the audit table.

The generated audit is:

- `data/ncbi_taxonomy_name_updates.csv`

The harmonised taxonomy table is:

- `data/resultado.cds.tax.ncbi_current.tab`

## Preservation of scientific values

Before and after harmonisation, the script verifies:

1. identical OTU matrix dimensions;
2. identical OTU row and column identifiers;
3. exact equality of every numeric OTU cell;
4. identical global count checksum;
5. identical taxonomy-table dimensions and feature identifiers.

Any numeric difference stops execution. The original `data/resultado.cds.tax.tab` is restored after figure generation.

## Figure regeneration

Figures 2–5 are regenerated by the canonical script:

- `scripts/generate_final_domain_taxonomy_figures.py`

The harmonisation runner temporarily supplies the current-name taxonomy table to the canonical generator and then restores the original packaged table. The generator retains the existing figure sizes, sample order, Dry/Rainy panel arrangement, Top-N selection, palette and graphical structure. Existing colours are transferred from legacy names to their current NCBI labels.

The regeneration report is written to:

- `reports/NCBI_TAXONOMY_HARMONIZATION_REPORT.json`

It records count checks and before/after aspect ratios for Figures 2–5. A change in figure aspect ratio above the configured tolerance stops execution.

## App correspondence

The Streamlit app uses `src/article_taxonomy.py`, which reads the same CDS OTU and taxonomy sources used by the article generator. Bacteria and Archaea are filtered before rank aggregation. Dry and Rainy are rendered as separate interactive panels, with Dry on the left and Rainy on the right. The app compares the interactive percentages against the source matrices exported for Figures 2 and 3.

The interactive alpha-diversity boxplot reads the exact source table used for Supplementary Figure 4:

- `data/final_publication_derived/SupplementaryFigure4_alpha_diversity_CDS_32999_source.csv`

It preserves the article group order, palette and rarefaction depth of 32,999 CDS.
